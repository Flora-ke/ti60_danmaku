# 离线素材

素材选自 `https://github.com/cusnaruto/UET_Danmaku` 原仓库的 `assets/`。仅取背景、灵梦、芙兰和三种子弹图片，不携带音乐、完整字体或原游戏引擎。没有重新绘制图片。

## 转换与运行时

运行时使用 `assets/assets.c` 的 `const uint16_t` 像素数组，头文件为 `include/assets.h`，不需要图片解码、文件系统或 SDL。数据是逐行 RGB565 数值；代码没有把 CPU 指针当设备地址使用，接入 DMA 时需由板级层完成地址和缓存处理。

精灵的原始 alpha 小于 128 时写成 `0xF81F` 色键；大于等于 128 时为不透明像素。转换后不做半透明混合。恰好量化成色键的不透明洋红像素改为 `0xF81E`，避免被错误隐藏。背景始终作为不透明图片处理。缩放采用最近邻，保留像素风格。

| 对象 | 原图与裁切 | 板上尺寸 |
| --- | --- | --- |
| 背景 | background.png 整图 800×920 | 400×300 |
| 灵梦 | reimu.png 三行各取第一个 32×48 帧 | 每帧 16×24 |
| 芙兰 | flan.png 完整 43×69 | 21×34 |
| 环形弹 | flanBullet.png 完整 16×16 | 8×8 |
| 扫射弹 | flanbullet2.png 完整 10×17，原游戏以两倍尺寸显示 | 10×17 |
| 玩家弹 | playerbullet.png 左侧箭头 21×23 | 6×7 |

原游戏灵梦动画使用高 49 的裁切框，但图片实际为 256×144，即 8 列、3 行的 32×48 图块。这里修正行高，避免第三行越界。原玩家弹请求的 24×29 框也高于原图 42×23，改取一枚完整箭头。所有裁切在生成时严格检查边界，完全透明的精灵会报错。

全部像素数组合计 **244284 字节（238.56 KiB）**；这是目标端像素占用，不是 C 源文本大小。额外的 `GameSprite` 元数据大小取决于目标指针宽度和对齐。具体 SHA-256、原图尺寸、裁切范围、有效像素数和碰撞替换数见 `assets/manifest.json`。SHA-256 按逐行小端 16 位像素计算，避免主机端序影响资源核验。

## 重复生成

离线工具依赖 Python 3 和 Pillow（本次使用 12.3.0，HPND 许可证）。目标板无需这些依赖。在本目录执行：

```powershell
python tools/convert_assets.py --source 'D:\Desktop\2026FPGA\UET_Danmaku-local\UET_Danmaku-master\assets'
```

也可指定其他原图路径或 `--output-root`。输出只覆盖指定输出根目录内的 `assets/assets.c` 和 `assets/manifest.json`。仅更换 Pillow 版本可能改变元数据版本字段；当前转换只使用整数 RGB565 量化和最近邻缩放。
