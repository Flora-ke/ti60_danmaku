# 每个文件在做什么

先读game.h理解“当前游戏有哪些数据”，再读game_step理解“一个逻辑周期发生什么”，最后看平台main如何周期性调用。CPU仍是取指/执行；游戏代码决定更新哪些数字，renderer把这些数字对应的图片写入帧缓冲。

```text
电脑版：SDL按键 → game_step(60Hz) → game_render(30Hz) → SDL显示
板卡：UART完整状态 → CLINT节拍 → game_step → game_render → 两张DDR图像
                                                        ↓
                  未来真实显示适配器：缓存清理/交接帧 → 显示控制器 → 屏幕
```

当前最后这条显示路径未接通，程序会明确拒绝出屏。RAM诊断明确只计算内存图像。

| 文件 | 完成的任务和逻辑 |
|---|---|
| include/game.h | 定义坐标、按键、状态、Game和Bullet数据结构，公开初始化/逻辑步进/哈希接口。位置和速度都以256为一个像素单位。 |
| src/game.c | 固定数组保存敌弹512和玩家弹64；整数方向表生成放射弹，扫射速度按相位变化。每步处理命令边沿、玩家和Boss移动、冷却、生成、移动与回收、碰撞、生命和胜负。重开一次性清空状态。 |
| include/render.h | 约定CPU绘图函数，步长单位为像素；调用者必须提供整帧可写内存。 |
| src/render.c | 写RGB565背景与侧栏，按游戏坐标贴共享图片，用色键跳过透明像素。精灵裁到战斗区，字库为内置5×7点阵。没有硬件寄存器或堆分配。 |
| include/assets.h | GameSprite宽、高、像素指针及透明色约定。 |
| assets/assets.c | 离线生成的常量图片数组，直接进入程序只读数据；子弹只保存种类，不拥有贴图副本。 |
| assets/manifest.json | 每张图尺寸、像素字节数、来源哈希和色键统计；用于核对内存与重生成结果。 |
| include/board_port.h | UART快照协议、超时策略与未来显示适配器的函数契约。 |
| platform/board_port.c | CRC8、半帧/坏帧恢复、断线释放按键；默认显示函数返回不可用。与BSP无关，可以在电脑测试。 |
| platform/sapphire_main.c | 使用真实Sapphire UART与CLINT；静态双缓冲；限制追帧、采样输入、逻辑更新、CPU绘图、UART遥测。常规模式必须成功接入显示；RAM诊断模式输出帧哈希用于确认真的绘图。 |
| platform/game_ddr.ld | 为独占游戏规划2MiB DDR和64KiB栈，提供start.S实际需要的符号。没有指定外设帧地址；仅是待链接核验的RAM布局。 |
| platform/host_main.c | SDL2窗口预览和无窗口PPM导出，共用同一game/render；图形层不使用SDL_image、ttf或mixer。命令按下保留到逻辑周期，防止极短按键漏采。 |
| tools/convert_assets.py | 只在电脑运行：裁图、缩放、alpha阈值转换、RGB565与C数组生成。不会在板卡上运行Python。 |
| tools/uart_bridge.py | 电脑串口输入桥，30Hz发送带CRC的完整位图；退出释放全部按键；pyserial仅为电脑可选依赖。 |
| tools/validate.py | 重现本机RV32语法检查、ASan/UBSan测试和SDL dummy启动检查，日志写到build/validation.json；工具链和BSP路径针对本机目录。 |
| tests/test_game.c | 检查完整演示确定性、上限、长期随机输入、重开/暂停、碰撞只扣一命、胜负、边界和计时回绕。 |
| tests/test_render.c | 用带保护区和额外stride的帧缓冲检查越界；包含负坐标和部分离屏精灵。 |
| tests/test_board_uart.c | 检查CRC、同步、坏帧、未知按键、半帧超时、断线释放，以及默认显示不可用。 |
| Makefile | 电脑构建、测试和RV32源码检查；不带自动下载或烧写动作。 |
| README.md / PROGRESS.md | 当前可运行范围、使用命令、内存与验证结果。 |
| docs/板卡接入.md / 素材说明.md | BSP、显示接口、UART协议和素材转换细节。 |

## 与原版的关系

原游戏是C++ ECS + SDL2。板端版保留芙兰和灵梦素材、放射与双扫射的玩法，重写为固定容量C程序。为减少无FPU CPU的开销，采用整数方向表；高档发射更快、相邻轮方向偏转；不保留原版角度单位错误。玩家动画裁图修正了原图行高与原代码不一致的问题。没有移植原来的多Boss流程、音频和完整菜单。
